# 4단계 — 기본 게임 수직 단면

## 1. 첫 작업 범위

첫 수직 단면은 다음 흐름을 실제 런타임에 연결한다.

```text
키보드 입력
    → PlayerInputIntent
    → PhysicsSchedule 수평 제어
    → Avian 충돌 해결
    → BB_FME 벽 반동
```

현재 입력은 `A`/`←`, `D`/`→`를 지원한다. 일반 이동의 Unity 기준선은 다음과 같다.

| 항목 | 값 |
|---|---:|
| 일반 제어 목표 속도 | 5.0 |
| 입력 가속도 | 20.0 unit/s² |
| 무입력 감속도 | 8.0 unit/s² |
| 정지 임계값 | 0.5 |
| 물리 주기 | 50 Hz |
| 벽 최소 반동 속도 | 12.0 |

`5.0`은 전역 속도 제한이 아니다. 벽 반동이나 능력으로 얻은 외부 속도는 같은 방향 입력에서 보존되며, 반대 입력이나 무입력일 때만 각 제어율로 0 또는 제어 목표를 향한다.

## 2. 벽 반동과 일반 입력의 자동 검증

`tests/player_control_wall_response.rs`는 실제 Avian 스케줄에서 왼쪽과 오른쪽 벽 충돌을 각각 발생시킨 뒤 다음 세 궤적을 10틱 동안 확인한다.

| 반동 직후 상태 | 틱당 변화 | 10틱(0.2초) 뒤 기준 |
|---|---:|---:|
| 반동 방향 입력 | 0.00 | -12.0 |
| 무입력 | +0.16 | -10.4 |
| 벽 쪽 반대 입력 | +0.40 | -8.0 |

검증 명령:

```bash
cargo test --test player_control_wall_response
```

전체 회귀 검증:

```bash
cargo test
```

## 3. 수동 체감 검증 맵

`DevelopmentMapPlugin`은 `assets/maps/phase4_player_control_sandbox.json`을 연다. 플레이어 양옆에 충분한 간격의 벽과 아래쪽 바닥이 있어 `cargo run` 직후 다음 항목을 반복 확인할 수 있다.

1. 벽을 향해 계속 입력했을 때 최소 속도 12로 반대 방향 반동하는가
2. 반동 방향 키를 이어서 누르면 강한 반동 속도가 보존되는가
3. 입력을 놓으면 반동이 천천히 감쇠하는가
4. 다시 벽 쪽 키를 누르면 즉시 방향이 뒤집히지 않고 점진적으로 주도권을 되찾는가
5. 좌우 벽에서 동작이 대칭적인가

## 4. 체감 조정 판단 기준

현재 값은 Unity 원본 환산값이므로 첫 검증에서는 변경하지 않는다.

- 반동 자체가 약하거나 벽 충돌의 존재감이 부족하다면 벽 반동 규칙을 조정한다.
- 평상시 이동까지 둔하다면 일반 가속도 `20.0`을 조정한다.
- 평상시 이동은 좋은데 반동 후 방향 전환만 늦다면 일반 가속도를 올리지 않고 별도의 `reversal_acceleration`을 도입한다.
- 키를 놓았을 때 너무 오래 미끄러진다면 무입력 감속도 `8.0`을 조정한다.

이렇게 분리해야 한 가지 체감 문제를 고치면서 평상시 이동, 벽 반동, 대시 속도를 동시에 훼손하지 않는다.
