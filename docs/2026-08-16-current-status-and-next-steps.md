# BB_FME Bevy 현재 진행 상태와 다음 작업 순서

작성일: 2026-08-16  
기준 커밋: `2fcd500 feat: camera follow`  
현재 단계: **4단계 기본 게임 수직 단면 진행 중**

## 1. 한눈에 보는 현재 상태

0단계의 Unity 정적 기준 문서, Unity JSON 호환 모델, 블록 설정 검증,
ECS 맵 생성·표시, Avian2D 물리 기준선까지 구현되어 있다.

현재 실행 파일에서는 개발용 JSON 맵을 읽어 공·별·일반 블록·가시를 생성하고,
공의 바닥 바운스·천장 접촉·벽 반동, 키보드 좌우 이동, 카메라 추적을 확인할 수 있다.

아직 별 수집, 가시 사망, 재시작, 클리어, 타이머, 점프 블록이 게임 규칙으로
연결되지 않았으므로 4단계 수직 단면은 완료 상태가 아니다.

```text
Unity 형식 JSON
    -> MapDocument 역직렬화
    -> 설정/맵 검증
    -> ValidatedMap
    -> SpawnValidatedMap
    -> 새 PlayWorld와 블록 Entity 생성
    -> 역할/스프라이트/Collider 부착
    -> 50Hz Avian2D 물리
    -> BB_FME 반동 규칙 + 플레이어 입력
    -> 카메라 추적
```

## 4. 다음 작업 순서

아래 순서를 하나씩 완료하고 검증한 뒤 다음 항목으로 이동한다.

### 1순위. 현재 카메라·입력 체크포인트 닫기

목표: 지금 커밋을 경고 없이 재현 가능한 기준점으로 만든다.

작업:

- 카메라 Query에 type alias를 적용해 Clippy 오류 제거
- `block_colliders` 테스트의 불필요한 `mut` 제거
- 카메라 추적의 ECS 통합 테스트 추가
- `docs/phase-4/README.md`에 카메라 규칙과 수동 검증법 기록
- A/D·방향키, 벽 반동, 수직 dead zone, 맵 가장자리 clamp를 직접 플레이 확인

완료 조건:

- `cargo fmt --all -- --check` 통과
- `cargo clippy --all-targets -- -D warnings` 통과
- 기본 테스트와 장기 바운스 테스트 통과
- 수동 체감 결과와 조정 여부가 문서에 기록됨

### 2순위. 실제 Unity JSON 골든 fixture 확보

목표: 합성 맵이 아니라 Unity가 실제로 만든 데이터로 호환성을 증명한다.

작업:

- Unity 에디터에서 최소 수직 단면 맵 1개를 만들고 JSON 원문 보존
- 공, 별, 일반 블록, 가시, 점프 블록, 옵션 1개 이상 포함
- Rust에서 역직렬화 -> 검증 -> 직렬화 round-trip 비교
- 원본 필드, 좌표, 방향, 옵션이 손실되지 않는 테스트 추가

완료 조건:

- Unity에서 내보낸 JSON을 Bevy가 코드 수정 없이 읽음
- 저장 후 의미와 보존 대상 필드가 유지됨
- fixture의 출처와 생성 절차가 문서화됨

### 3순위. 최소 플레이 세션과 상호작용 수집 단계 만들기

목표: 별·가시가 같은 물리 틱에 닿아도 실행 순서가 흔들리지 않는 기반을 만든다.

권장 최소 타입:

```rust
enum PlaySessionState {
    Playing,
    Dead,
    Cleared,
}

struct PlaySession {
    state: PlaySessionState,
    collected_stars: u32,
    elapsed_seconds: f32,
}
```

작업:

- PhysicsSchedule에서 trigger/contact를 먼저 수집
- 게임 규칙 시스템이 수집 결과를 한 번에 처리
- 우선순위를 `사망 -> 이동/포탈 -> 수집 -> 스위치 -> 반동`으로 명시
- 세션이 `Playing`이 아니면 입력과 타이머가 진행되지 않게 연결

완료 조건:

- 이벤트 도착 순서를 바꾼 테스트에서도 같은 결과
- 같은 틱에 별과 가시가 닿으면 사망이 우선
- 물리 수집과 게임 규칙 변경이 서로 다른 시스템으로 분리됨

주의: 여기서는 4단계에 필요한 최소 세션만 만든다. 메뉴·에디터 테스트 모드까지
포함하는 전체 AppState 설계는 6단계에서 확장한다.

### 4순위. 별 수집 구현

목표: 별 접촉이 플레이 진행 데이터로 연결되게 한다.

작업:

- 별에 Sensor Collider 부착
- 접촉 시 한 번만 수집
- `collected_stars` 증가
- 수집된 별의 표시와 충돌 비활성화
- `GridIndex`에 죽은 Entity를 남기지 않도록 수명 정책 결정

권장 방식: 수집 즉시 Entity를 없애기보다 `Collected` 상태로 바꾸고 표시·Sensor를
비활성화한다. 재시작 시 PlayWorld 전체를 다시 만들면 원본 별이 자연스럽게 복원된다.

완료 조건:

- 같은 별을 여러 틱 접촉해도 1회만 증가
- 복수 별의 수집 수가 정확함
- 재시작 후 모든 별이 복원됨
- headless 테스트 통과

### 5순위. 가시 사망 구현

목표: 가시 접촉이 결정적인 사망 상태로 이어지게 한다.

작업:

- 기존 가시 Sensor의 CollisionStart를 상호작용 수집 단계에 연결
- 세션을 `Dead`로 전환
- 입력 중지와 공 물리 정지 또는 사망 연출용 상태 분리
- 중복 사망 이벤트 방지

완료 조건:

- 가시 방향별 Sensor 접촉에서 한 번만 사망
- 별과 가시 동시 접촉 시 별이 증가하지 않음
- 사망 뒤 입력·타이머가 진행되지 않음

### 6순위. PlayWorld 전체 재생성 방식 재시작

목표: 오브젝트를 일일이 되돌리지 않고 원본 맵에서 깨끗하게 재시작한다.

작업:

- 현재 `PlayWorld`가 가진 불변 `ValidatedMap`으로 새 spawn 요청 생성
- 기존 PlayWorld root 제거 후 전체 재생성
- 세션, 별, 공 위치·속도, 카메라를 초기 상태로 되돌림
- 개발 중에는 `R`, 이후 UI 버튼과 같은 restart command를 공유

완료 조건:

- 사망 전후 어느 시점에서도 재시작 가능
- 별을 먹은 뒤 재시작하면 별과 카운터가 모두 초기화
- 자동 테스트에서 동일 맵 100회 재시작 후 Entity·상태 누수 없음

### 7순위. 클리어·타이머·최소 HUD

목표: 플레이 시작부터 클리어까지 한 사이클을 화면에서 확인한다.

작업:

- 필요 별 수와 수집 수 비교
- 마지막 별 수집 틱에 `Cleared` 전환
- 플레이 중에만 타이머 증가, 사망·클리어 시 정지
- 최소 HUD에 별 수, 시간, Dead/Clear 상태, 재시작 안내 표시

완료 조건:

- 마지막 별을 먹으면 정확히 한 번 클리어
- 클리어 시간이 이후 프레임에서 변하지 않음
- 사망한 틱에는 클리어가 발생하지 않음
- 재시작하면 타이머와 HUD가 초기화

### 8순위. 점프 블록과 맵 경계

목표: 최초 수직 단면에 필요한 마지막 핵심 블록과 실패 조건을 연결한다.

작업:

- `fb_jump`를 조합형 역할/컴포넌트로 분류
- 접촉 방향과 현재 중력을 기준으로 점프 속도 적용
- 맵 밖 추락/이탈의 기준을 Unity 실행으로 먼저 확인
- 결정된 경계 규칙을 사망 또는 위치 제한으로 구현
- 점프 직후 고속 이동에서 CCD 재검증

완료 조건:

- 방향별 점프 블록이 기대 방향으로 작동
- 모서리 중복 발동 없음
- 경계 밖 플레이어가 영구히 사라지지 않음
- 점프 직후 얇은 블록 관통 테스트 통과

### 9순위. 4단계 수직 단면 최종 검증

목표: 실제 Unity JSON 맵으로 시작·플레이·사망·재시작·클리어를 완주한다.

검증 시나리오:

1. 골든 JSON 맵 로드
2. 좌우 이동과 일반 바운스
3. 가시에 닿아 사망
4. 재시작
5. 점프 블록 사용
6. 모든 별 수집
7. 타이머가 멈추며 클리어

완료 조건:

- 위 한 사이클을 수동 플레이로 완주
- 별·사망·재시작·클리어 핵심 규칙은 headless 테스트 보유
- `fmt`, 엄격한 `clippy`, 기본 테스트, 장기 물리 테스트 모두 통과
- 4단계 문서에 결과와 알려진 제한 기록

### 10순위. 5단계 전체 블록 이식 시작

4단계가 끝난 뒤에만 다음 순서로 확장한다.

```text
5-A 정적 블록과 단순 위험물
    -> 5-B 플레이어 능력
    -> 5-C 스위치와 상태 블록
    -> 5-D 이동·동적 블록
    -> 5-E 포탈·레이저·기어·스윙 등 고난도 블록
```

각 블록은 구현과 동시에 독립 테스트 맵, 정상 동작 테스트, 재시작 복구 테스트,
조합 테스트를 추가한다.

## 5. 지금 바로 시작할 작업

다음 구현 작업은 **1순위 카메라·입력 체크포인트 닫기**다.

그 다음에는 기능을 더 붙이기 전에 **2순위 실제 Unity JSON fixture**를 확보한다.
현재 합성 JSON과 개발용 JSON만 있으므로 이 증거가 없으면 “Unity 맵 호환 완료”라고
확정할 수 없다.

이 두 체크포인트 이후 첫 신규 게임 기능은 별이나 가시를 곧바로 콜백에서 처리하는
것이 아니라, **3순위 상호작용 수집·우선순위 단계와 최소 PlaySession**을 먼저 만드는
것이다. 이 기반이 있어야 이후 포탈·아이템·스위치가 늘어도 충돌 순서 버그가 퍼지지 않는다.
